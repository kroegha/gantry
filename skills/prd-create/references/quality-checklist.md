# PRD Quality Checklist

## Overview

Use this checklist to verify the quality and completeness of generated PRD documents.

---

## Pre-Generation Checklist

### Requirements Gathering

- [ ] Product name and description captured
- [ ] Core problem clearly identified
- [ ] Target users defined
- [ ] Must-have features listed
- [ ] Technical requirements gathered
- [ ] Integration needs documented
- [ ] Timeline expectations noted
- [ ] Any ambiguities clarified with user

### Market Research

- [ ] Direct competitors identified (minimum 3)
- [ ] Competitor features analyzed
- [ ] Feature comparison matrix created
- [ ] Differentiation strategy defined
- [ ] Technology research completed
- [ ] Research sources documented

---

## Document Structure Checklist

### Market Research Document

- [ ] Executive summary present
- [ ] Market overview section complete
- [ ] All competitors profiled
- [ ] Feature comparison matrix included
- [ ] Differentiation strategy clear
- [ ] Technology recommendations included
- [ ] Sources listed in appendix

### PRD Document

- [ ] Cover page with correct metadata
- [ ] Document control table complete
- [ ] Revision history initialized (v1.0)
- [ ] Table of contents structure correct
- [ ] All required sections present
- [ ] Annexures properly structured

---

## Content Quality Checklist

### Executive Summary

- [ ] Vision statement clear and compelling
- [ ] Product overview concise
- [ ] Key differentiators highlighted
- [ ] Readable by non-technical stakeholders

### Problem Statement

- [ ] Current challenges clearly stated
- [ ] Target users well-defined
- [ ] Pain points specific and measurable
- [ ] Evidence/data included where available

### Scope Definition

- [ ] In-scope items explicit
- [ ] Out-of-scope items explicit
- [ ] Future considerations noted
- [ ] No ambiguous scope boundaries

### User Stories

- [ ] Stories follow "As a [user], I want [action], so that [benefit]" format
- [ ] All user types have stories
- [ ] Stories are specific and testable
- [ ] Stories map to features

### Functional Requirements

- [ ] Requirements have unique IDs
- [ ] Requirements are specific and measurable
- [ ] Priority assigned to each requirement
- [ ] Requirements trace to user stories
- [ ] No duplicate requirements
- [ ] No conflicting requirements

### Non-Functional Requirements

- [ ] Performance requirements specified
- [ ] Security requirements defined
- [ ] Scalability targets set
- [ ] Usability standards referenced
- [ ] Accessibility requirements (WCAG level)
- [ ] Requirements are measurable

### Technical Architecture

- [ ] System overview provided
- [ ] Technology stack specified
- [ ] Integration points documented
- [ ] Data architecture outlined
- [ ] Rationale for technology choices

### Implementation Roadmap

- [ ] Clear phases defined
- [ ] MVP scope identified
- [ ] Phase dependencies noted
- [ ] Logical progression

### Success Metrics

- [ ] KPIs defined
- [ ] Metrics are measurable
- [ ] Targets specified
- [ ] Measurement methods noted

### Risks and Mitigations

- [ ] Technical risks identified
- [ ] Business risks identified
- [ ] Each risk has mitigation strategy
- [ ] Risk severity/likelihood noted

---

## Writing Quality Checklist

### Clarity

- [ ] No jargon without definition
- [ ] Sentences are concise
- [ ] Active voice preferred
- [ ] One idea per paragraph

### Consistency

- [ ] Terminology consistent throughout
- [ ] Formatting consistent
- [ ] Section numbering correct
- [ ] Cross-references accurate

### Completeness

- [ ] No placeholder text remaining
- [ ] No TBD/TODO items unresolved
- [ ] All sections have content
- [ ] Examples provided where helpful

### Accuracy

- [ ] Technical details verified
- [ ] Competitor information current
- [ ] Statistics have sources
- [ ] No contradictions within document

---

## Format Quality Checklist

### Markdown File

- [ ] Headers properly formatted
- [ ] Tables render correctly
- [ ] Code blocks formatted
- [ ] Lists properly indented
- [ ] Links work (internal references)
- [ ] No raw HTML unless necessary

### Word Document

- [ ] Cover page styled correctly
- [ ] Document control table formatted
- [ ] TOC generates properly
- [ ] Heading styles applied
- [ ] Tables have zebra striping
- [ ] Headers/footers present
- [ ] Page numbers correct
- [ ] CONFIDENTIAL marker on cover

---

## Final Review Checklist

### Before Delivery

- [ ] All three documents generated:
  - [ ] Market Research Markdown
  - [ ] PRD Markdown
  - [ ] PRD Word Document
- [ ] Filenames follow convention
- [ ] Version numbers correct (v1.0)
- [ ] Dates current
- [ ] Author information correct

### User Presentation

- [ ] Summary of documents prepared
- [ ] Key decisions highlighted
- [ ] Open questions listed
- [ ] Next steps suggested

## Common Issues to Check

### Content Issues

| Issue | How to Check |
|-------|--------------|
| Vague requirements | Search for "should", "might", "could" |
| Missing acceptance criteria | Check each requirement has measurable outcome |
| Scope creep | Verify features match agreed scope |
| Contradictions | Cross-reference related sections |

### Format Issues

| Issue | How to Check |
|-------|--------------|
| Broken cross-references | Test all "See Section X" links |
| Inconsistent numbering | Review section number sequence |
| Missing styling | Visual inspection of Word doc |
| Table formatting | Check all tables render correctly |

### Completeness Issues

| Issue | How to Check |
|-------|--------------|
| Missing sections | Compare against template |
| Empty annexures | Review all annexure content |
| Placeholder text | Search for "[", "TBD", "TODO" |
| Missing sources | Check appendix has all references |

## Iteration Checklist

### After User Feedback

- [ ] All feedback items logged
- [ ] Changes prioritized
- [ ] Updates applied
- [ ] Version incremented if significant
- [ ] Both Markdown and Word updated
- [ ] Changes verified

- [ ] All requested changes made
- [ ] Final quality check passed
- [ ] Documents ready for distribution
